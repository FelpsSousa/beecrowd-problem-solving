# Problem Solving Framework

This is the default thinking process for approaching a new problem.

## 1. Restate the problem

Explain the problem in simple words.

If I cannot explain it clearly, I probably do not understand it yet.

## 2. Identify the essentials

- What is the input?
- What is the output?
- What constraints matter?
- What must be optimized?
- What can be ignored?

## 3. Start from the baseline

What is the brute-force solution?

Even a bad first solution helps reveal structure and constraints.

## 4. Look for the pattern

Questions to ask:

- Is this about arrays, strings, simulation, recursion, or graphs?
- Is order important?
- Is this a search problem?
- Is this a counting problem?
- Is there repeated work?
- Is there a structure that should be stored explicitly?

## 5. Choose the simplest correct approach

The goal is not to look clever.

The goal is to solve the problem correctly, clearly, and within constraints.

## 6. Validate complexity

Before coding, estimate:

- time complexity
- space complexity
- why this approach fits the constraints

## 7. Implement cleanly

- meaningful names
- simple control flow
- avoid unnecessary shortcuts
- prefer readability

## 8. Review after acceptance

After solving:

- what pattern did this teach?
- what mistake almost happened?
- what should be remembered next time?
