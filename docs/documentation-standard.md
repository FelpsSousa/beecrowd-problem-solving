# Documentation Standard

This repository uses three documentation levels.

The purpose is to balance quality and scale.

## L1 &mdash; Quick Log

Use for:

- easy problems
- direct problems
- routine practice
- repetition-based training

Minimum required fields:

- problem id
- title
- link
- topics
- language(s)
- summary
- core idea
- time complexity
- space complexity
- status

## L2 &mdash; Standard

Use for:

- medium problems
- meaningful patterns
- relevant implementation choices
- mistakes worth preserving

Recommended sections:

- summary
- my interpretation
- core idea
- approach
- why this works
- complexity
- edge cases
- what I learned

## L3 &mdash; Deep Dive

Use for:

- hard problems
- elegant problems
- milestone problems
- reusable conceptual patterns

Recommended sections:

- why this problem matters
- failed ideas
- mental model
- full reasoning
- alternative approaches
- complexity trade-offs
- generalization
- revisit triggers

## Rule of Sustainability

Excellence does not mean maximum documentation for everything.

Excellence means building a repository that remains useful, consistent, and maintainable over time.
